# Jev AI (TypeSafe): применимость в Clinical Case Scoring Platform

## Контекст

Jev — первый «System One»-модель от TypeSafe AI (релиз 15.09.2026). Это **не LLM**: он
не генерирует текст, а принимает `state` (текст/JSON/массив) и карту типизированных
вопросов, возвращая типизированные ответы с калиброванной вероятностью за 70–500 мс.
Три примитива: `noul` (да/нет), `choice` (одна из заранее заданных опций), `score`
(оценка по заданной шкале).

Документ отвечает на вопрос: полезна ли Jev здесь и почему — в первую очередь в контексте
идеи «дешёвые токены и оптимизация».

## 4. Что Jev может и чего не может здесь

| Задача системы | Компонент | Jev | Почему |
|---|---|---|---|
| Извлечение структурированного кейса из сырого текста (title/description/questions/options) | pipeline | ❌ | Это генерация произвольного текста; Jev текст не генерирует, а `choice`/`score` работают только по заранее заданным опциям/шкале |
| Детерминированный подсчёт баллов | backend | ❌ (и не нужно) | Инвариант системы — воспроизводимый детерминизм; Jev вероятностный |
| Оценка качества извлечения | pipeline / harness | ✅ | Verification — целевой сценарий Jev |
| Гейт/классификация входа (клинический ли текст, специальность) | pipeline / input | ✅ | `noul` + `choice` по фиксированному списку категорий |
| Приоритизация/сложность кейса | сервисный | ✅ | `score` по шкале |

**Вывод:** Jev не заменяет ядро системы (извлечение + скоринг), а дополняет его
вспомогательными «маленькими решениями».

## 5. Где Jev подходит в первую очередь

1. **Harness-судья качества извлечения** — проверка/оценка результата поверх текущих
   per-field precision/recall/F1. Целевой кейс Jev: проверка выходов других моделей.
2. **Input-гейт до извлечения**: `is_clinical` (`noul`) + `specialty` (`choice`) — отсев
   нерелевантного ввода и маршрутизация.
3. **Guardrail перед `POST /cases`** — проверка кейса перед записью в БД.
4. **Приоритизация/сложность кейса** (`score`) — вспомогательный сигнал для методиста.

**Анти-список (не подходит):** замена extraction-LLM; любой шаг в детерминированном
подсчёте баллов; hot-path пользовательского запроса в backend.

## 6. Плюсы (факты)

- **Скорость:** 70–500 мс против секунд у LLM.
- **Цена:** $0.042 за 1M входных токенов, **выходные бесплатны**.
- **Нет парсинга ответа:** типизированный вывод, «zero structured-output errors» by construction.
- **Калиброванная уверенность:** у `choice`/`score` есть confidence, у `noul` — вероятность
  0–1; на этом строятся пороги «автоматически / на проверку».
- **Простая интеграция:** один endpoint `POST /v1/systemone`; официальный Python SDK
  `typesafe-sdk` (есть async-клиент, ≥3.10).
- **Несколько вопросов за один вызов** — считаются параллельно по одному `state`.

**Про «дешёвые токены»:** дешевизна Jev — прямое следствие того, что он **не выполняет
генерацию** (не пишет текст, а выбирает из заданного). Поэтому экономия не переносится на
основную нагрузку — извлечение кейса из текста, где нужен именно LLM-генератор. Jev
удешевляет только вспомогательные решения (проверка, классификация, скоринг), и там
экономия реальна.

## 7. Минусы и риски

| Риск | Суть | Митигация |
|---|---|---|
| **Русский язык** | Данные системы (raw.txt, golden) — на русском; официально заявлено, что не-английский может работать хуже | Проверить на golden-наборе до внедрения |
| **Только облако** | Self-host невозможен, инференс только у вендора | Для клинических данных учитывать egress и политику данных |
| **Приватность** | Сырой клинический текст уходит третьей стороне; free-tier может использоваться для обучения | Не отправлять реальные данные на free-tier; ключ только через env / Secret Manager |
| **Зрелость/доступ** | Early access / waitlist; на старте API перегружался | Не закладывать в критический путь; предусмотреть fallback |
| **Calibration ≠ гарантия** | Официальные docs требуют порогов и human review | Использовать как сигнал, а не как истину |
| **Недоверенные сайты** | Вокруг Jev много неофициальных «ресселлеров» | Использовать только `typesafe.ai` и официальный SDK |
| **Закрытость** | Архитектура модели не раскрыта, вендор молодой | Воспринимать как внешнюю зависимость с риском |

## Итог

Jev полезен как дешёвый и быстрый слой проверки/классификации/скоринга вокруг системы, но
**не** как замена LLM-извлечению и **не** как замена детерминированному подсчёту баллов.
Ценность — во вспомогательных решениях, а не в экономии на основной extraction-нагрузке.
